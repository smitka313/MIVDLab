Set up your two micro:bits

One program, two BBC micro:bit V2 boards. Use the same downloaded HEX file on both boards. You need one battery pack for the car-mounted board and a USB data cable for the receiver.

Step 1 — Download: Download the updated universal micro:bit program (.hex).

2. Install the same program on both micro:bits

  1. Connect the first micro:bit V2 to a computer with USB.
  2. Copy the downloaded .hex file onto the MICROBIT drive and wait for it to finish.
  3. Repeat with the second micro:bit. Both boards use the identical file.

3. Set up the wireless receiver (RX — default mode)

  1. Connect one micro:bit to the computer using USB.
  2. Power on or reset normally. Do not hold A. The display should show RX followed by a checkmark.
  3. The receiver writes RX_READY to USB serial at startup. Open the device serial console in Microsoft MakeCode, with the receiver connected. Depending on browser and pairing, you may need to connect/pair the device in MakeCode. The console does not always open automatically when using a precompiled HEX.
  4. Live values appear when the car is recording and in radio range. If no live readings appear, verify that the car is in CAR mode and recording; confirm both boards have this same HEX.

4. Set up the car recorder (CAR — hold A during reset)

  1. Attach the battery pack to the other micro:bit.
  2. Hold button A while powering on or pressing Reset; release it once startup begins. The display should show CAR.
  3. Mount the board flat, LEDs facing up and top edge pointing toward the front of the car. Secure it away from wheels, gears and steering parts.
  4. With the car still on level ground, press A again to calibrate and start recording. Wait for CAL to finish before driving.
  5. Drive the test, stop the car and press B to end recording. The peak mph displayed is an experimental estimate, not verified speed.

5. Export and analyze a run

  1. Connect the car micro:bit to the computer by USB.
  2. Open its MY_DATA page and export the recording as a CSV.
  3. Click Import CSV files in MIVD Telemetry Lab. The current 10-column universal telemetry format is supported.
  4. Select a run, review the graphs, record the vehicle setup and compare controlled trials.

Quick startup reference

Normal startup = RX (USB receiver).
Hold A while resetting = CAR (battery-powered recorder).
In CAR mode, press A again after startup to calibrate and record; press B to stop.

What gets logged?

Each car sample includes run, time_ms, ax_mg, ay_mg, az_mg, forward_ms2, lateral_ms2, pitch_deg, roll_deg, speed_est_mph. The dashboard derives acceleration magnitude and a motion/vibration proxy from the raw axes.

Measurement limits: This system does not measure true speed, distance, or battery energy. Estimated speed drifts, and pitch/roll readings are affected by acceleration. Compare repeated, similar tests.

Troubleshooting: If the receiver shows CAR, reset it normally without holding A. If the car shows RX, hold A while resetting it. If serial data is absent, check the USB data cable, device console, car recording status, and radio range. If CSV import fails, export MY_DATA from the car, not the receiver.

MIVD Telemetry Lab — User Manual

Welcome to MIVD Telemetry Lab. This guide explains what to click, what the numbers mean, and how to turn test results into engineering decisions. Start with the quick steps, or search for a feature.

Fastest path: Program both micro:bits → record a run → import CSV → compare one modification → write Claim–Evidence–Reasoning → save evidence.

1. Getting started

The dashboard has four workspaces: Collect Data (set up and import), Analyze (graphs and measurements), Test & Compare (gearing and repeated trials), and Report (CER and graph evidence). Move through them left to right; use the tabs to return to any step.

Updated startup controls: the USB receiver starts in RX mode normally. To use the car recorder, hold A while pressing Reset or powering on, then press A again to calibrate and record. Press B to stop. Both boards use the same downloaded HEX.

Start here: Set up → Record → Import → Analyze → Decide.

  1. Choose Set Up micro:bits in the top banner. Download the provided HEX and load the same file onto both BBC micro:bit V2 boards.
  2. Connect the receiver board by USB and start it normally (do not hold A); it should show RX. On the battery-powered vehicle board, hold A while powering on or resetting to select CAR.
  3. Mount the vehicle board flat and securely, LEDs up and top edge forward. Keep it still on level ground. Press A to calibrate and start; press B to stop.
  4. Connect the vehicle board by USB, open MY_DATA, export CSV, and import it here.
  5. For practice, select Try example data. Sample runs are simulated, not real measurements.

The USB receiver is for live serial viewing in MakeCode; this dashboard analyzes the vehicle board's saved CSV after the run. Save your CSV before reflashing or clearing data.

2. Importing and selecting runs

Keep track of which recording you are viewing.

  1. Expand Quick Start if needed and choose Import CSV files. You can import multiple recordings.
  2. Choose an Active run and optionally a Compare with run.
  3. Look for the run name above each graph, metrics panel, events list, and data table.
  4. For a fair comparison, use similar test courses and driving conditions. Record setup details separately in Engineering Testing.

The universal program records ten columns: run, time_ms, ax_mg, ay_mg, az_mg, forward_ms2, lateral_ms2, pitch_deg, roll_deg, speed_est_mph. The dashboard derives some additional values from those readings.

Bigger numbers are not always better.

4. Reading and customizing graphs

Explore one measurement or compare two runs.

  1. Expand Telemetry Graphs and Comparisons. Read the graph title and units.
  2. Use the graph key to identify each line. Solid lines represent the selected run; dashed lines represent the comparison run.
  3. Click a legend item to hide or restore that line. You can isolate one measurement without removing its dataset.
  4. Hover over a time-series plot to inspect a recorded timestamp and value.
  5. Set a start and end time to focus on a maneuver, then use Reset View to restore the full run.
  6. Click a time-series graph to open the observation editor. Write a note, select Save note, or cancel. Saved notes appear beneath the graph and in exports.
  7. Use each graph's Download PNG button or Download All Graphs to export evidence. Hidden lines and run labels should be reflected in exports.

For the G–G diagram, each point represents forward versus sideways acceleration. Above/below center suggests accelerating/braking; left/right suggests turning. It is an approximate vehicle-dynamics view, not a map of the track.

Graph smoothing: what the slider does

Smoothing makes a jagged graph easier to read by averaging nearby measurements. Your micro:bit senses small vibrations and bumps, so readings can jump up and down even during steady driving. The slider controls how many nearby samples are averaged into each displayed point.

  • 1 sample — Raw view: No additional graph smoothing. Best for checking sudden braking, impacts, and unusual spikes.
  • 5 samples — Starting point: A useful balance for spotting overall acceleration and turning trends.
  • 11–21 samples — Stronger smoothing: Makes broad patterns clearer but can flatten peaks and hide brief events.

Example: At about 10 readings per second, 5 samples cover roughly half a second. The actual time span depends on the recorded sample rate.

Important: Smoothing does not improve sensor accuracy or change the imported CSV. A smoother line is not proof of a smoother or better-driving vehicle. Compare runs using the same setting, and switch back to 1 sample to check any important peaks before drawing conclusions or exporting evidence.

5. Comparing two recordings

Focus on the same maneuver under similar conditions.

  1. Choose an Active run and Comparison run.
  2. Inspect their superimposed traces; turn off unnecessary lines using the legend.
  3. Look at the difference graph: Comparison minus Active. Positive means the comparison has a larger signed value at that moment—not necessarily better performance.
  4. Use time-range selection or the run-alignment reference to compare the same launch, corner, or braking event.
  5. Read the Run comparison table and percentage changes. Decide whether the change matches the event goal, and repeat the trial.

If one driver started accelerating earlier than another, comparing the same clock time may be misleading. Align comparable events before drawing conclusions.

6. Guided testing and multiple trials

A good experiment changes one thing at a time.

  1. Expand Competition Testing and Engineering Reports or Guided testing lab.
  2. Select the competition event and name the setup clearly (for example, “Stock tires / asphalt”).
  3. Record driver, tires, spur and pinion, shock/differential fluids, battery, drivetrain, surface, and conditions as applicable.
  4. Collect at least three comparable trials per setup when practical. Enter actual lap time, laps, or other event result manually; attach telemetry if available.
  5. Use the multi-trial averages, ranges and consistency tools and setup rankings. Lower average times are usually preferable for timed events; more laps are preferable for lap-count events.
  6. Review the controlled experiment checker for changes in driver, course, surface or multiple variables.
  7. Read the data quality checker before trusting unusual peaks or speed estimates.

The automatic engineering guidance is a starting point, not a final verdict. Ask whether the change improved the actual competition result and whether the result repeats.

8. Gearing and vehicle budget

Use the calculators as planning tools.

  1. Expand Spur & Pinion Gear Ratio Calculator. Enter the spur teeth and pinion teeth for the current and proposed setups.
  2. Ratio = spur teeth ÷ pinion teeth. A lower numerical ratio generally favors potential wheel speed; a higher ratio generally favors torque multiplication.
  3. Record the gearing on each test so you can link changes to results.
  4. Use the Vehicle Budget tool to enter the base car retail value and upgrades. Review the running total against the guidebook's $2,000 build budget.

Actual acceleration and top speed depend on the whole drivetrain, motor, battery, tires, and conditions. The calculator does not establish race compliance.

9. Engineering reports and evidence exports

Show the decision and the data behind it.

  1. Use Engineering Decision Journal or the guided testing CER fields.
  2. Claim: predict which setup should perform better. Evidence: give numerical results, averages, and graphs. Reasoning: explain how the data supports or challenges the claim.
  3. Document what stayed constant and what you will change next.
  4. Use Download Evidence Summary, Download engineering report, or Print Report as appropriate.
  5. Insert downloaded PNG graphs into an engineering journal or presentation, with run names and units visible.

A one-run difference is not proof. Explain uncertainty, repeatability, and any measurement limitations.

10. Saving, restoring and sharing work

Back up before switching computers or clearing browser data.

  1. Export the complete project backup after entering tests and annotations.
  2. To continue later, use Import / Restore Project where available, and check which records were restored.
  3. Keep original CSV files, PNG exports and reports in your team folder as separate evidence.
  4. Do not rely solely on browser storage: private browsing, browser resets or a different computer may not retain it.

Project backups and report exports may cover different parts of the workspace. Confirm that your imported runs and annotations are present after restoring a backup.

13. Autosave, evidence board and accessibility

Complete workspace backup: use Download workspace backup to save recordings, evidence, and engineering testing records in one JSON file. Use Restore workspace backup to load it on another computer. Refresh after restoring to reload all forms.

Autosave: your selected view and locally loaded recordings are saved in this browser when possible. Look for the last-saved status. Browser storage may be cleared, blocked or full, so download a complete project JSON backup before leaving or switching computers.

Evidence board: choose a graph, click Save graph to evidence, add a short caption, and print the board or Save as PDF. Each image is a snapshot of the graph at that moment; save it again if you change the graph. Only the latest few image snapshots are retained locally to avoid browser storage limits.

Keyboard and touch: use Tab to move between controls, Enter or Space to activate buttons, and the labelled expand/collapse sections to navigate. If a section is not visible, open its workspace tab and expand the relevant section.

Recommended workflow: import → inspect data confidence → record setup → repeat trials → compare → select graph evidence → write your CER conclusion → export project backup.
