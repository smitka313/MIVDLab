Set up your micro:bit

One program, one BBC micro:bit V2 on the car. You need a battery pack for the micro:bit and a USB data cable to download your data. Everything is recorded on the car, so nothing else is required. A second micro:bit is optional and only shows live values on a computer while the car drives.

Step 1 — Download: Download the updated universal micro:bit program (.hex).

2. Install the program on the car's micro:bit

  1. Connect the micro:bit V2 to a computer with USB.
  2. Copy the downloaded .hex file onto the MICROBIT drive and wait for it to finish.
  3. Optional: if you want live values, repeat with a second micro:bit. Both boards use the identical file.

3. Set up the car recorder (CAR — hold A during reset)

  1. Attach the battery pack to the car's micro:bit.
  2. Hold button A while powering on or pressing Reset; release it once startup begins. The display should show CAR.
  3. Mount the board flat, LEDs facing up and top edge pointing toward the front of the car. Fix it firmly with foam tape or screws so it cannot wobble (secure the battery pack and its wire too, and use fresh batteries), and keep it away from wheels, gears, steering parts, the motor and speed-control wires.
  4. Direction check (automatic): turn the car on, set it still and level, and press A. The first press after the micro:bit starts is always the direction check. Wait for CAL, the checkmark and the diamond, then push the car straight forward by hand within 8 seconds. The display shows + or −, then a small diamond (ready). If you see an X icon, press A again and push more firmly. If it shows SIDE, the micro:bit is mounted sideways: turn it so the top edge points to the front. This keeps braking from being recorded as acceleration. Touch the logo any time to repeat it.
  5. Put the car back at the start, still and level, and press A again. The board calibrates (the display shows CAL) and then starts recording. If it shows MOVE, the car was moving. TILT means the car is more than about 15° off level. ERR means the sensor reading looked wrong. Fix the problem and press A again. Wait for the checkmark and then the diamond icon before driving.
  6. Drive the test, stop the car and press B to end recording. It shows the run number (for example #4302, write it on your run log) and then the peak speed index, an estimate and not a verified speed. While recording, the top-left LED blinks.
  7. Tip: start each run from a stop and finish with a full stop when you can. The board resets its speed index when it detects about one second of stillness, which keeps the estimate from drifting.

4. Export and analyze a run

  1. Connect the car micro:bit to the computer by USB.
  2. Open its MY_DATA page and export the recording as a CSV.
  3. Click Import CSV files in MIVD Telemetry Lab. The current 10-column universal telemetry format is supported.
  4. Before the log fills up: the car stores only a limited amount of data (roughly 2 to 3 minutes of driving in total). The display shows FULL and logging stops when it is full. Export your CSV first, then clear the log: press A+B (DEL?) and A+B again within 3 s, or copy the .hex file onto the MICROBIT drive again.
  5. Select a run, review the graphs, record the vehicle setup and compare controlled trials.

5. Optional: add a second micro:bit for live values (RX — default mode)

  1. Connect one micro:bit to the computer using USB.
  2. Power on or reset normally. Do not hold A. The display should show RX followed by a checkmark.
  3. The receiver writes RX_READY to USB serial at startup. Open the device serial console in Microsoft MakeCode, with the receiver connected. Depending on browser and pairing, you may need to connect/pair the device in MakeCode. The console does not always open automatically when using a precompiled HEX.
  4. Live values appear when the car is recording and in radio range. If no live readings appear, verify that the car is in CAR mode and recording; confirm both boards have this same HEX.

Quick startup reference

Normal startup = RX (optional live-values receiver).
Hold A while resetting = CAR (battery-powered recorder).
In CAR mode: A = direction check on the first press after startup, then calibrate and start recording. B = stop (or calibrate only when idle). A+B = clear the data log (shows DEL?; press A+B again within 3 s to confirm; export first!). Logo touch = repeat the direction check.

What gets logged?

Each car sample includes run, time_ms, ax_mg, ay_mg, az_mg, forward_ms2, lateral_ms2, vib_rms_mg, peak_g, speed_est_mph. Each row is the average of about 10 readings taken at 100 Hz. vib_rms_mg is the vibration inside that 0.1 s and peak_g is the largest single reading (impact indicator). Older files with pitch_deg and roll_deg still load.

Measurement limits: This system does not measure true speed, distance, or battery energy. The speed index is an estimate that can be off by 25% or more, and the tilt graph only shows apparent tilt caused by acceleration. Compare repeated, similar tests.

Troubleshooting: If the receiver shows CAR, reset it normally without holding A. If the car shows RX, hold A while resetting it. If serial data is absent, check the USB data cable, device console, car recording status, and radio range. If CSV import fails, export MY_DATA from the car, not the receiver. If the car shows MOVE, TILT or ERR after you press A, calibration was rejected: hold it still and level, then press A again. If braking looks like acceleration, touch the logo to repeat the direction check. If it shows FULL, export the CSV, then press A+B twice to clear the log. If pressing A only scrolls "HOLD A + RESET FOR CAR", the board started as a receiver: hold A while pressing Reset.

Test-day checklist

You only need the car, one micro:bit with its battery pack, and a computer. Do one run at a time and change only one thing between runs.

Before the first run

  1. ☐ Car battery charged. Micro:bit battery pack attached.
  2. ☐ Micro:bit flat on the chassis, LEDs up, top edge toward the FRONT, fixed with tape or screws (no wobble, away from the motor and wires).
  3. ☐ Hold A and press Reset: display shows CAR.
  4. ☐ Turn the car on. Car still and level. Press A (direction check), wait for the diamond, then push the car straight forward. Display shows + or −. (Happens automatically after every reset.)

For every run

  1. ☐ Write the run on the log below (setup, what changed).
  2. ☐ Car on, still and level at the start line. Press A. Wait for CAL, checkmark, then the diamond. (MOVE, TILT or ERR means try again.)
  3. ☐ Drive the planned test. Finish with a full stop if you can.
  4. ☐ Press B to stop. Write down the run number it shows (#…), the speed number and your stopwatch result.

After testing

  1. ☐ Plug the micro:bit into the computer. Open MY_DATA and download the CSV.
  2. ☐ Import the CSV in Collect Data. Rename each run to its setup name in Analyze.
  3. ☐ Clear the log for the next team only after the CSV is saved: press A+B (DEL?) and A+B again within 3 s.

MIVD Telemetry Lab — User Manual

Welcome to MIVD Telemetry Lab. This guide explains what to click, what the numbers mean, and how to turn test results into engineering decisions. Start with the quick steps, or search for a feature.

Fastest path: Program the micro:bit → record a run → import CSV → compare one modification → write Claim–Evidence–Reasoning → save evidence.

1. Getting started

The dashboard has four workspaces: Collect Data (set up and import), Analyze (graphs and measurements), Test & Compare (did the change help, and repeated trials), and Report (CER and graph evidence). Move through them left to right; use the tabs to return to any step.

Startup controls: the USB receiver starts in RX mode normally. To use the car recorder, hold A while pressing Reset or powering on (CAR). With the car still and level, press A: the first press is the direction check (push the car forward once when the diamond shows). Then press A again to calibrate and record. Press B to stop. A second micro:bit, if you use one, uses the same HEX.

Start here: Set up → Record → Import → Analyze → Decide.

  1. Choose Set Up micro:bit in the top banner. Download the provided HEX and load it onto your BBC micro:bit V2. (A second micro:bit is optional and uses the same file.)
  2. On the car's micro:bit, hold A while powering on or resetting to select CAR. (Optional: a second micro:bit started normally shows RX and displays live values over USB.)
  3. Mount the vehicle board flat and securely, LEDs up and top edge forward. Keep it still on level ground. Press A once and push the car forward when the diamond shows (direction check). Then press A again to calibrate and start; press B to stop.
  4. Connect the vehicle board by USB, open MY_DATA, export CSV, and import it here.
  5. For practice, select Try example data. It loads two simulated practice runs of the same 3-lap oval: a control run on stock tires and a run with one change, grippier tires. Practice finding the evidence: the grippier tires launch, brake and corner harder and finish the 3 laps about 2.5 s sooner. In Test & Compare, Load practice trials adds matching stopwatch times. Sample runs are simulated, not real measurements.

The optional second micro:bit is only for live serial viewing in MakeCode; this dashboard analyzes the vehicle board's saved CSV after the run. Save your CSV before reflashing or clearing data.

2. Importing and selecting runs

Keep track of which recording you are viewing.

  1. In Collect Data, choose Import CSV files. You can import multiple recordings. A box then asks you to name each new run after its setup (for example Control: stock tires); you can also rename runs later in Analyze.
  2. Open Analyze. At the top, type a Run name for each run (for example "Stock tires"), then pick a Run to view and, if you want, a run to Compare with. To compare three to five recordings, open Analyze → Multi-run overlay — compare up to five recordings.
  3. What happened in this run (top of Analyze) tells the story of the run in plain words: launch, strongest acceleration, hardest braking, top speed index, each corner and lap times. Set Corners per lap to match your course (2 for an oval or figure-8, 4 for a rectangle). Laps are timed from the middle of the same corner each lap. The same moments are labelled on the graphs (Launch, Strongest launch, Hardest braking, Top speed index, C1, C2…).
  4. Simple view shows only forward acceleration, speed index and cornering. Choose All graphs for vibration, the G-G diagram, apparent tilt, difference graphs and sampling details.
  5. Accelerations are shown in g (1 g = 9.8 m/s², the pull of gravity), with an everyday comparison such as "like a sports car launching".
  6. Look for the run name above each graph, metrics panel, events list, and data table. Time zero (next to the run name) sets whether graphs start at your first launch or when you pressed A. Use First launch to compare runs fairly, even if one driver started later.
  7. For a fair comparison, use similar test courses and driving conditions. Record setup details separately in Engineering Testing. In the multi-run tool, check up to five runs, use Show first two or Show up to five as shortcuts, and use Hide all to clear the selection.

The universal program records ten columns: run, time_ms, ax_mg, ay_mg, az_mg, forward_ms2, lateral_ms2, vib_rms_mg, peak_g, speed_est_mph. The dashboard derives some additional values from those readings.

3. Understanding the measurements

Bigger numbers are not always better.

MeasurementWhat it tells youBe careful
Forward accelerationHow strongly the car speeds up or brakes along its length.Tilting, bumps and sensor calibration can change readings.
Cornering (sideways) accelerationSideways force during turns and sudden direction changes.Higher values alone do not prove better grip.
Apparent pitch / rollTilt implied by the accelerometer, calculated from forward and lateral acceleration.Hard acceleration and turns distort these angles.
Total G / impactTotal g-force (the largest reading in each 0.1 s); spikes may show bumps.Includes gravity; spikes are not confirmed collisions.
Vibration (ride roughness)How rough the ride is. The v3 firmware measures vibration at 100 Hz and logs it for every 0.1 s (vib_rms_mg). Older logs can only estimate it.Rough ground, tires, gears and the motor all add vibration. It is not suspension travel.
Speed index (estimated)Forward acceleration added up over time. It resets to zero when the car is stopped and slowly forgets old data.Can be off by 25% or more, and more in long runs without stops. Not a verified speed or top speed.

Check your own car: in Analyze, open Optional · Check how accurate your speed index is. Drive a taped course of known length, enter its length, and the dashboard shows how far off the speed index was. Three checks tell you how large a difference between setups you can trust. It needs only a tape measure and a stopwatch.

Use real stopwatch times, lap counts, or external speed measurements for competition outcomes. The micro:bit measurements provide supporting evidence.

4. Reading and customizing graphs

Explore one measurement, compare two runs in detail, or overlay up to five recordings.

  1. Expand Telemetry Graphs and Comparisons. Read the graph title and units.
  2. Use the graph key to identify each line. Solid lines represent the selected run; dashed lines represent the comparison run.
  3. Click a legend item to hide or restore that line. Hiding a line does not delete its data.
  4. Hover over a time-series plot to inspect a recorded timestamp and value.
  5. Set a start and end time to focus on a maneuver, then use Reset View to restore the full run.
  6. Click a time-series graph to open the observation editor. Write a note, select Save note, or cancel. Saved notes appear beneath the graph and in exports.
  7. Use each graph's Download PNG button or Download All Graphs to export evidence. Hidden lines and run labels should be reflected in exports. For the separate Multi-run overlay, each recording has a distinct color; click its legend label to hide or restore it and choose Download PNG under an overlay graph to save that comparison.

For the G–G diagram, each point represents forward versus sideways acceleration. Above/below center suggests accelerating/braking; left/right suggests turning. It is an approximate vehicle-dynamics view, not a map of the track.

Graph smoothing: what the slider does

Smoothing makes a jagged graph easier to read by averaging nearby measurements. Your micro:bit senses small vibrations and bumps, so readings can jump up and down even during steady driving. The slider controls how many nearby samples are averaged into each displayed point.

  • 1 sample — Raw view: No additional graph smoothing. Best for checking sudden braking, impacts, and unusual spikes.
  • 3 samples — Starting point: Matches the peak numbers on the cards. 5–9 samples: easier to see overall acceleration and turning trends.
  • 11–21 samples — Stronger smoothing: Makes broad patterns clearer but can flatten peaks and hide brief events.

Note: with the v3 firmware, each logged row is already an average of about 10 readings, so even 1 sample is lightly smoothed. Example: At about 10 rows per second, 3 samples cover roughly 0.3 seconds. The actual time span depends on the recorded sample rate.

Important: Smoothing does not improve sensor accuracy or change the imported CSV. A smoother line is not proof of a smoother or better-driving vehicle. Compare runs using the same setting, and switch back to 1 sample to check any important peaks before drawing conclusions or exporting evidence.

5. Comparing recordings

In Analyze, open Multi-run overlay to select up to five recordings. Use the checkboxes to add or remove runs, click a run label to hide its line, and review the multi-run summary table. The original two-run comparison and difference graphs remain available for close comparisons.

Focus on the same maneuver under similar conditions.

  1. In Analyze, pick a Run to view and a run to Compare with at the top of the page.
  2. Look at the two lines on top of each other, and turn off lines you do not need using the legend.
  3. Look at the difference graph: Comparison minus Active. Above zero means the compare-with run read higher at that moment, which is not always better.
  4. Use Time zero = First launch (top of Analyze) so both runs line up at the same launch, and compare the same corner or braking point.
  5. Read Did the change help? at the top of Test & Compare for the verdict, the percentage changes and which differences are bigger than measurement noise. Then repeat the trial.

If one driver started accelerating earlier than another, comparing the same clock time may be misleading. Align comparable events before drawing conclusions.

Two runs or five? Use the Run to view / Compare with graphs to study one change in detail and see difference graphs. Use Analyze → Multi-run overlay — compare up to five recordings when you want to see trends across several runs or vehicle setups.

Step by step: Compare up to five recordings

  1. Import at least two CSV runs in Collect Data.
  2. Open Analyze, then expand Multi-run overlay — compare up to five recordings.
  3. Check the runs you want to compare (maximum five). Start with two to keep the graphs readable.
  4. Match each line to its run using the colored legend; click a legend entry to hide or show that run.
  5. Read the Multi-run summary table for duration, peak acceleration, braking, cornering g and vibration. Peak speed index is not verified speed.
  6. Click Download PNG beneath a graph to save the visible comparison for your engineering report.

Curves follow the Time zero setting at the top of Analyze; First launch lines the runs up at their launch. The same timestamp may represent different maneuvers, so compare similar driving tests and repeat trials before deciding which setup is better.

6. Guided testing and multiple trials

A good experiment changes one thing at a time.

  1. Open Test & Compare. At the top, Did the change help? automatically compares a control run with a changed run and says whether performance improved, got worse, stayed about the same, or traded one thing for another. It ignores differences smaller than measurement noise and uses your stopwatch trials as the official result when you have them.
  2. Press ✍️ Start my CER from this result to copy the claim and evidence into the Report journal. The reasoning is left for you to write.
  3. Then use 1 · Quick trial comparison for repeated stopwatch trials, or 2 · Detailed competition test record for a full setup log.
  4. Select the competition event and name the setup clearly (for example, “Stock tires / asphalt”).
  5. Record driver, tires, spur and pinion, shock/differential fluids, battery, drivetrain, surface, and conditions as applicable.
  6. Collect at least three comparable trials per setup when practical. Enter actual lap time, laps, or other event result manually; attach telemetry if available.
  7. Use the multi-trial averages, ranges and consistency tools and setup rankings. For timed events, a lower average time is better; for lap-count events, more laps is better.
  8. Review the controlled experiment checker for changes in driver, course, surface or multiple variables.
  9. Read the data quality checker before trusting unusual peaks or speed estimates.

The automatic engineering guidance is a starting point, not a final verdict. Ask whether the change improved the actual competition result and whether the result repeats.

Where to begin: In Test & Compare, start with Quick trial comparison for repeated results, or Detailed competition test record for a full setup log. The gear calculator is optional. Finish your CER and download reports in the Report workspace.

8. Gearing and vehicle budget

Use the calculators as planning tools.

  1. Expand Spur & Pinion Gear Ratio Calculator. Enter the spur teeth and pinion teeth for the current and proposed setups.
  2. Ratio = spur teeth ÷ pinion teeth. A lower numerical ratio generally favors potential wheel speed; a higher ratio generally favors torque multiplication.
  3. Record the gearing on each test so you can link changes to results.
  4. Use the Vehicle Budget tool to enter the base car retail value and upgrades. Review the running total against the guidebook's $2,000 build budget.

Actual acceleration and top speed depend on the whole drivetrain, motor, battery, tires, and conditions. The calculator does not establish race compliance.

9. Engineering reports and evidence exports

Show the decision and the data behind it.

  1. Open the Report tab. First save graphs in 1 · Evidence collection board, then write your Claim, Evidence and Reasoning in 2 · Engineering decision journal.
  2. Claim: predict which setup should perform better. Evidence: give numerical results, averages, and graphs. Reasoning: explain how the data supports or challenges the claim.
  3. Document what stayed constant and what you will change next.
  4. In 3 · Generate reports from saved vehicle tests (or the buttons in the journal), use Download Evidence Summary, Download engineering report, or Print Report as appropriate.
  5. Insert downloaded PNG graphs into an engineering journal or presentation, with run names and units visible.

A one-run difference is not proof. Explain uncertainty, repeatability, and any measurement limitations.

13. Autosave, evidence board and accessibility

Complete workspace backup: in Collect Data, open Save or move your work and use Download workspace backup to save recordings, evidence, and engineering testing records in one JSON file. Use Restore workspace backup to load it on another computer. Refresh after restoring to reload all forms.

Autosave: your selected view and locally loaded recordings are saved in this browser when possible. Look for the last-saved status. Browser storage may be cleared, blocked or full, so download a complete project JSON backup before leaving or switching computers.

Explanations: every graph and number has a ▸ What it means line. Tap or click it (or press Enter) to open the explanation; they start closed to keep pages short.

Evidence board: choose a graph, click Save graph to evidence, add a short caption, and print the board or Save as PDF. Each image is a snapshot of the graph at that moment; save it again if you change the graph. Only the latest few image snapshots are retained locally to avoid browser storage limits.

Keyboard and touch: use Tab to move between controls, Enter or Space to activate buttons, and the labelled expand/collapse sections to navigate. If a section is not visible, open its workspace tab and expand the relevant section.

2027 guidebook: 1/10-scale electric RC car; motor at most 3800 KV, 540 can size or smaller; one motor; battery and safety rules vary by event.

Most events specify 2S 7.4V 5000mAh hardcase LiPo with 30C or lower. Top Speed specifies 3S 11.1V 5000mAh hardcase with 40C or lower, but organizers may limit it to 2S. Efficiency battery details remain to be announced.

What it means: A higher numerical ratio usually provides more wheel torque and lower wheel speed at the same motor RPM. A lower numerical ratio usually gives more potential wheel speed but less torque multiplication. Actual acceleration, speed, and motor temperature also depend on the motor, battery, tires, and track.
How to use this in a test: Run Setup A, change only the gearing, and repeat the same driving test with Setup B. Compare acceleration, braking, and stability graphs. Do not use the micro:bit's estimated top speed alone to judge which gearing is faster.

Formula: external ratio = spur teeth ÷ pinion teeth. This is not the complete drivetrain final-drive ratio; internal transmission and differential reductions are not included. Check your vehicle's gearing limits and motor temperatures before changing gears.
